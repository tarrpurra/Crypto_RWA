Critical pre-construction truths
Know before you start
USDY and mETH are real deployed assets — read-only for you
You cannot modify USDY or mETH contracts. Your agent interacts with them via their public ABIs. Your job is to build the decision layer (when to hold, when to swap) and the execution layer (calling DEX contracts). Study both token contract ABIs in week 1 before writing a single line of your own code.
Critical
Mantle testnet is your best friend — use it from day one
Mantle has a public testnet with a free faucet. All development and testing must happen here. Never spend real tokens. The Byreal RealClaw platform also has a sandbox environment. Set this up on day 1 — late environment setup kills hackathons.
Important
The "AI" layer does not need to be GPT-4 — simpler wins here
Judges want to see intelligent decision-making, not expensive API calls. A well-designed rule engine with LLM-readable justifications, or a local Ollama model, can be more impressive than a GPT-4 wrapper. This also solves the zero-budget constraint entirely.
Advantage
4 weeks with 3 developers is genuinely sufficient scope
Most hackathon teams have 48–72 hours. You have 4 weeks and 3 people. This means you can actually build something polished. The risk is scope creep — define your MVP on day 1 and protect it religiously.

Three realistic approaches for your team and timeline — each represents a different risk/reward tradeoff.

Recommended
Method 1 — Hybrid Agent (LLM brain + rule-based execution)
Difficulty 6.5/10
Build a Python off-chain agent that polls on-chain data (yield rates, TVL, oracle prices), feeds a structured prompt to a local LLM (Ollama + Mistral/LLaMA3 — totally free), and receives a decision. The decision triggers a pre-audited Solidity executor contract on Mantle that performs the actual swap or hold. Risk management lives in the Python layer as a guardrail that can veto any AI decision if risk thresholds are breached.

Method 2 — Fully On-chain Rule Agent (no LLM)

"AI" is represented by the deterministic, transparent on-chain logic. More truly decentralized and trustless, but much harder to build correctly and audit under time pressure.

Zero-budget AI strategy
Use Ollama locally for development, Gemini free tier for production demos
During the 4 weeks of building: run LLaMA 3.2 8B locally via Ollama — zero cost, fast iteration, no rate limits. This hybrid approach costs nothing and gives you the best of both worlds.

A realistic 4-week sprint for 3 intermediate developers. Each week has a shippable milestone so you always have something to show.

  • Install Ollama locally, run first LLaMA 3.2 prompt

  • Read Byreal Skills CLI docs and RealClaw template code
  • Define your MVP scope document — pin it, don't change it

Week 2

  • Dev 2: Write Solidity executor contract — accept instruction, call DEX swap
  • Dev 3: Build risk management module — Pyth oracle feed reader + threshold checks
  • Wire them together: agent → risk check → executor → testnet transaction
  • Write unit tests for the executor contract (Hardhat or Foundry)
  • Log every agent decision to a local file (preparation for on-chain logging later)

Six real threats to your project — and how to neutralize each one before it becomes a problem.

DEX integration is harder than it looks
Merchant Moe and Agni Finance are Uniswap V2/V3 forks but with Mantle-specific quirks. Slippage, pool liquidity on testnet, and token approval flows trip up most intermediate devs.
→ Fix: In week 1, manually execute a swap on Mantle testnet via Etherscan to understand the exact calldata before you write a single line of Solidity.
LLM decisions may be too slow for a live demo
Local LLaMA 3.2 on consumer hardware can take 10–30 seconds to respond. In a live demo, 30 seconds of silence looks broken.
→ Fix: Pre-compute a set of "replay" decisions from a real run to show in the demo. Keep the live call available, but have the replay as a fallback. Always have a fallback.
Scope creep will kill you
4 weeks feels long. It's not. Adding "just one more feature" in week 3 is how teams end up with a half-finished dashboard and no working agent on demo day.
→ Fix: Write your MVP features on a physical list on day 1. Any feature not on the list requires a team vote to add. Protect the core ruthlessly.
Pyth oracle data not available for testnet
Some price feeds exist on Mantle mainnet but not the testnet, forcing you to mock risk data. Judges may question whether risk management is real.
→ Fix: Use Pyth's Hermes REST API (free) to pull off-chain prices into your Python agent as a proxy. Clearly document that mainnet would use the on-chain feed.
Gemini free tier rate limits during the live demo
15 requests/minute sounds fine until you demo to judges and the API returns a 429 at the worst possible moment.
→ Fix: Implement a local Ollama fallback. If the Gemini call fails, the agent silently switches to the local model. Judges won't notice the difference in a demo.
ERC-8004 is a very new standard with thin documentation
The agent identity NFT standard (ERC-8004) is new and may have sparse examples or incomplete tooling. Time-boxing this badly can eat your week 3.
→ Fix: Treat ERC-8004 as a "nice to have" in week 1 scoping. Build a simple ERC-721 fallback for agent identity that works reliably. Upgrade to ERC-8004 only if time allows in week 3.
